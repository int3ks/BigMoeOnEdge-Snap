# BigMoeOnEdge+ Changelog

## Snap fork

- Models page: a model's load status lives in its own card. Loading, the loaded model's details with Reload / Unload, and a failed load show at the top of that model's card, which opens by itself; the separate status card at the top of the page is gone (it only returns for a state no listed model belongs to). The load has a real progress bar: the engine reports which step it is in and how far (`bmoe/load_progress.h`, JNI `nativeLoadProgress`, polled every 250 ms into `EngineState.Loading.step/fraction`): reading the model (llama.cpp's own tensor progress), the MTP drafter, finding the experts, loading the weights into RAM (by bytes read) and preparing the NPU, with the elapsed time. The chat's banner shows the step too.
- Version numbers move only with a release: a build carries the version the next release will have (one past the newest release tag, e.g. 0.6.54 after v0.6.53), so the builds between two releases share it instead of counting up with every commit; the APK name still has the commit. A build shows its version as a notice on the run page.
- Editing a message, regenerating an answer, switching chats or the first turn after a reload no longer throw the engine's context away. The app replays the conversation for these (`clear_kv=true`), and the engine used to clear the KV first, so the whole conversation was prefilled again even when only its last message changed. Now the replay is diffed against what the context holds, token for token, as the API server's requests already were: the shared beginning is kept and only the rest is prefilled (on Qwen3.5/3.6, Gemma and other recurrent/sliding-window models from the newest context checkpoint before the change). A different chat shares at most its system prompt, so nothing of another conversation leaks in. Without a tracked prefix (raw prompts, a template that failed, a scored-choice request that overwrote the context) the KV is cleared as before. Host tests: an edit, a regenerate and a chat switch answer byte-identically to a fresh session on a dense llama (regenerate reuses 78 of 79 tokens) and on the hybrid Jamba.
- Engine updates from upstream BigMoeOnEdge (0.34–0.36), ported onto this fork's 0.28-based engine so that its own changes (tool grammar, Guess ahead with temperature, NPU + MTP, multimodal, per-model KV type) stay as they are:
  - **Context checkpoints** (upstream 0.36): on models whose memory cannot be cut back to any position — Qwen3.5/3.6 (recurrent Gated DeltaNet layers), Gemma (sliding window), Jamba, Nemotron-H — a turn whose prompt differs from what the context holds no longer prefills the whole conversation again. The part of the state that cannot be cut is copied at the end of every prompt (and every 8192 tokens inside a long one) and restored at the newest copy before the difference; only the rest is prefilled. Helps agent rounds, a template that renders an answer back differently, an API client that resends the conversation, and a cancelled turn. Up to 4 copies, 320 MiB together (Qwen3.6-35B-A3B's is about 63 MiB; models that can be cut anywhere keep none). Lossless: tested against a fresh session on a hybrid attention + Mamba + MoE model. `context_checkpoints.{h,cpp}`, `SessionConfig::ctx_checkpoints / checkpoint_min_step / checkpoint_budget_mib`, new `KV_REUSE_CHECKPOINT`; logcat "Run stats" now shows `kv_reuse` and `n_reused`.
  - **Expert tensors read from the file** (upstream 0.34, #266): a MoE architecture that is not in `arch_registry.cpp` no longer fails with "no MoE recipe": a block's 3-D `.weight` whose third extent is the file's expert count is a routed expert. Architectures in the registry keep their row and slot order when the file holds exactly those tensors, so every model that streamed before streams the same way. Refusals say why (a dense file, layers that disagree, more than three expert tensors per layer). `bmoe/expert_layout.h`, `moe/expert_layout.cpp`.
  - **Cache brake** (upstream 0.34): when a token's compute takes twice this session's median and a sample of the expert cache's pages shows Android compressed or swapped some of them, the cache is halved (never below one token's worst-case cycle) instead of thrashing. Only shrinks; reloading the model starts from the configured size again. The first 4 tokens of each turn are not judged, so pages taken back while the app sat idle do not count. `engine/cache_brake.{h,cpp}`, `ExpertStreamSource::cache_lost_frac`, `MoeStreamConfig::cache_brake` (on); logged as "cache brake: …" and as `cache_mib` in the run stats.
  - **A read past the end of a model file is an error** (upstream #348): a truncated download or damaged shard fails the load instead of streaming whatever the read buffer held as expert weights.
  - Host tests for all four (`app/src/main/cpp/core/tests`, run with `scripts/host-engine-tests.sh`; the session test makes a tiny random Jamba model).
- CI: the NPU engine is cached by the git tree hashes of `app/src/main/cpp`, the two build scripts and the toolchain image digest; a push that changed none of them restores the engine instead of building it (~7 of ~11 minutes). When it has to be built, ccache (pinned 4.10.2, checksum-verified, cache kept between runs) skips unchanged objects. The APK job verifies the payload and signature either way.
- Mouse right-click in the chat input (also while editing a message) opens Cut / Copy / Paste / Select all / Share / Search the web at the pointer (`TextFieldWithMouseMenu`). Compose 1.6 has no such menu on Android: a right-click only moved the cursor and dropped the selection; touch selection with the system toolbar is unchanged.

Tool results (e.g. Termux output) have a Copy button and can be selected when expanded; notices and the live command output can be copied too.
- Loading asks only when there is a real risk (RAM, a fixed cache over 60 % of RAM, pinned weights, a suspiciously small file) or an error. The notes "regular (non-MoE) model" and "Guess ahead pauses for image turns" no longer open the dialog, so with n-gram on by default a model loads with one tap.
- Defaults: Guess ahead is n-gram (exact at any temperature, costs nothing when nothing repeats) and "prefer cached experts" is 15 %. Existing settings are kept.
- Models page: the model list is sorted by last use (the chat's model menu too); MTP drafters, LoRA adapters and vision projectors are listed below the models and show where the file is. Registered paths and attachments whose file was deleted are dropped (only when its folder can still be read, so an unreachable SD card keeps them). "Reload model" also appears when the loaded model's own settings changed (KV cache, LoRA, projector, drafter while Guess ahead is MTP), compared with what the load asked for, and a reload now takes the current attachments. The load warning about greedy decoding with Guess ahead is gone.
- Agent: the model is asked to keep scripts short (no comments or extras; a one-line command for a one-off step), and gets the last 1000 characters of a command's output (was 1500).
- Expert cache sizes in finer steps: 250 MiB up to 2000, 500 MiB up to 5000, then 6000/7000/8000; the Auto cap in 1000 MiB steps from 1000 to 8000. The auto-tuner picks from the same finer list.
- Guess ahead (MTP / n-gram) works with any temperature. Drafts are verified by DRAWING the target's token with the turn's own sampler at each position (the draft stays while the draw equals it, the first differing draw is the next token), so every token is a sample from the model's distribution exactly as without guessing; the engine no longer refuses spec + sampling (config.cpp) and the app no longer forces temperature 0 when guess ahead is on (it did so silently). The API server honours client sampling with guess ahead on as well. Fewer drafts are accepted at higher temperatures.
- Tool calls are written greedily: once the output contains `<tool_call>`, the rest of the turn is drawn at temperature 0 (the trigger is now sent whenever tools are enabled, also on reasoning turns without the grammar), so a call's name and JSON are the model's most likely tokens while the chat text before it keeps the chosen temperature. `ToolGrammarSampler::sample(logits, greedy)`; host test case (b2).
- The approval for replacing a file says Replace / Cancel (it said Delete); approvals can name their own button (`ConfirmationRequest.confirmLabel`).
- Fix: the approval dialog for a tool call often did not appear and the call waited forever (only with Approval *Ask*). `GenerationManager` changed its state with a plain read-modify-write from several threads; the "tool started" event, arriving at the same moment as the approval request, overwrote it. State changes are now atomic (`MutableStateFlow.update`), and the tool-started event keeps the approval line when the request came first.
- Approval in the chat's status row: while a tool waits for approval the row says "Waiting for your approval…", shows what is to be approved (e.g. the Termux command and folder) and has Accept / Reject right there, in addition to the dialog. Before, the row looked like a running command ("Termux: …" with a clock and Cancel) while the call was in fact waiting for an approval dialog the user did not see; Cancel then declined it and the model read that as a refusal. The tool's clock now starts once the call is approved. Found through the new command history: the "hanging" commands had never reached Termux.
- Agent prompt: an ENVIRONMENT block comes first — Android tablet, not Windows/macOS/a Linux server (no PowerShell, cmd, sudo, /root, /mnt/data), no built-in Python or sandbox, everything runs through run_shell in Termux, with an example call `python3 …`. Cancelling a command now tells the model that the user stopped a stuck command, not that they refused it.

## Unreleased - NPU prefill + MTP fix

- NPU prefill now works together with Guess ahead (MTP and n-gram). Before, three independent gates refused the combination: `config.cpp` ("prefill.device does not combine with speculative decoding"), `native-bridge.cpp` (rejected any `I_SPEC_SOURCE`) and the Settings switch (`npuCombinationAllowed`). Removing the gates alone would have been unsafe, so the engine was also fixed: the MTP draft pass during prefill ran while the target's weights were rebound to the device (and with the arena hooked in), and the MTP head's layer, experts and KV were pulled into the device rebind. See docs/NPU_MTP_FIX.md.
- The NPU "minimum prompt tokens" threshold must now exceed the speculative verify width (draft_max + 1); the app raises it automatically and the Settings list only offers valid values.
- A separate MTP sidecar GGUF is loaded CPU-only while NPU prefill is on, so it does not open a second HTP session.
- MTP / n-gram Guess ahead can now be loaded together with an mmproj. Before, `session.cpp` refused both at load and on any image turn. Image turns decode plainly (the engine already disabled drafting for them), and both contexts' KV is cleared around them, so text turns afterwards re-prefill target and draft consistently.
- Not compiled with the NDK/Hexagon toolchain and not run on a device in this environment.

## Signing fix

- Added a stable release signing key mechanism (`app/build.gradle.kts`, env/secrets driven) and updated the NPU CI workflows to require it, so future APKs share one certificate and install as updates. See docs/SIGNING.md.

## 0.6.0 — 2026-10-23

- **Auto settings** (Settings → top card): scans RAM, CPU cores/fast cores, SoC, a quick memory-speed test and whether the NPU runtime is available, then builds settings for the chosen model in three tiers: **Fastest**, **Balanced** and **Most accurate (slowest)**. MoE and dense models get different plans (expert cache, dropped/substituted experts, prefetch, guess-ahead, context, threads).
- Each save shows an **estimated tokens/second**; **Measure** loads the model with that save, generates 64 tokens and records the real speed, then restores the model that was loaded before. A "this may take a while" prompt shows a time estimate first, and measuring can be cancelled.
- **Saves**: named, switchable (Use), renamable, deletable, and downloadable/importable as small JSON files. Switching a save only changes the engine settings Auto settings owns; sampling, tools and theme are untouched.
- Measuring is crash-guarded: plans are kept inside a cautious RAM budget, a save that wouldn't fit is skipped instead of loaded, only one big load exists at a time, the screen stays on while measuring, and a crash marker lowers a save's memory use automatically if the app is killed mid-measurement. The Fastest tier no longer uses expert substitution, two-wave reads or a wide prediction window (the settings its first version crashed a 35B-A3B model with), and its expert-count cut is milder (8 → 6); older saves are cleaned automatically. NPU prefill is opt-in (off by default). Each save has a "Lower memory" button.
- Bumped to 0.6.0 (versionCode 11).

- Fixed NPU unavailable at runtime ("HTP0 was not registered (devices: CPU)"): the manifest now declares `<uses-native-library android:name="libcdsprpc.so" android:required="false"/>`, which Android 12+ requires before an app can load Qualcomm's FastRPC library that ggml-hexagon dlopen()s.
- Fixed the NPU payload verifier false-failing under `set -o pipefail` (`strings | grep -q` SIGPIPE); it now greps the binary directly.
- Bumped versionCode to 10 so the NPU build installs as an update instead of being mistaken for the CPU-only 0.5.8 APK.

## 0.5.8 — 2026-10-22

- Fixed the Android NPU workflow to run Gradle from the project root and use the correct root-relative APK path.
- Hardened the Hexagon CMake path with explicit SDK/toolchain validation, the existing `PREBUILT_LIB_DIR=android_aarch64` selector, a fresh build directory, and stale-output invalidation. The reported SDK `string(FIND...)` failure is not reproduced here and remains pending a real toolchain CI run.
- Updated the native-build container reference to the documented Snapdragon toolchain `v0.8` image and added ELF/backend-marker/payload validation before packaging and after extracting files back out of the APK.
- Made the Hexagon build script remove only its own staged libraries instead of deleting the entire `jniLibs/arm64-v8a` directory.
- Added a source-level NPU validator and made settings/upstream wiring validators follow the current app version instead of hard-coding 0.5.7.
- Clarified that a successful CI package is not proof of on-device HTP execution; runtime verification on a supported Snapdragon device is still required.

This is an NPU build-pipeline hardening change. It does not claim an APK has been built or benchmarked in this environment.

## 0.5.7 — 2026-10-22

- Reorganized Engine Performance into four grouped cards: Hexagon prefill, MoE streaming/I/O, speed/quality, and CPU compute/memory.
- Added native-wired controls for batch/prefill threads, ubatch width, sampling seed, two-wave I/O, row-stream window, NPU routing thresholds, N-gram matching, drop normalization/prefill, and expert-stream diagnostics.
- Added the upstream decision-prefix-cache policy to the scored-choice API settings.
- Added an explicit force switch for expert-cache sizes below 1500 MiB while keeping the previous BigMoeOnEdge+ default behavior.
- Enabled I/O/compute overlap in fresh-install defaults. The native build still reports overlap inactive when the expert-ready hook is absent or streaming/cache is unavailable.
- Made Hexagon/NPU controls visible in CPU-only builds, disabled with an explanation instead of hiding the settings.
- Added a source-level parity inventory separating supported options from unsupported desktop/GPU/planner/debug-only options.
- Preserved BigMoeOnEdge+ identity, API, database, MTP sidecar flow, and custom UI.

This is a settings/UI/native-wiring update on the existing local engine baseline, not a wholesale merge of upstream 0.33.x.
